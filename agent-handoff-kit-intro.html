01 / 一句講清楚

它只處理一件事:
AI 跨對話失憶。

這套工具的工作很窄,只是一件事:跨對話失憶。失憶不只是「上次做到哪」,還包括中途新建的文檔、你引入的參考資料。它的作用,是把進度、下一步、檔案登記寫進幾份固定文件,讓下一輪能自動接得回去。

未用這套工具

每次開新對話都要重新交代背景、貼舊文件、列哪些檔案是真源、哪些只是參考,然後再講上次做到哪。一旦交代得不齊,AI 就會憑空推斷,把參考檔當真源,或者把你已做完的事重做一遍。

用了之後

準備結束本輪工作時說一聲「收工」,AI 自動更新交接文件與檔案登記表,並同步更新 START_NEXT_SESSION_PROMPT.txt。下次在同一專案內說 Start Agent Handoff 或「開工」,下一個 AI 立即讀齊狀態:做到哪、下一步是甚麼、哪些檔案是真源、哪些只是參考。

02 / 解決四類常見問題

用 AI 做長期項目,
常見的四件事。

如果你曾經和 AI 講了一個小時,隔日回來它甚麼都不記得;又或者你建過好幾份新文檔、貼過幾份 PDF 給它做參考,下次它卻分不清哪份是真源——你已經遇上以下其中一個情況。

01

新 AI 不知做到哪

一個項目做幾天,中間試過 Codex、Claude Code、Claude Cowork、Antigravity 不同工具。每次開新對話都要重新交代;到後來,連你自己都不肯定哪個版本是最新。

這套工具用 SESSION_HANDOFF 文件記住「當前狀態 + 下一步」
02

新建檔案、引入資料變孤兒

AI 過程中會建立新文檔,你也會引入 PDF、Notion 連結、研究筆記作參考。這些檔案當下 AI 都記得,但新對話一開,它就分不清哪份是正式來源、哪份只是草稿,甚至不知道有這些檔案存在。

說「把這份文件接入 Agent Handoff Kit」,AI 會檢查它是否已接入索引、同步責任與相關流程
03

每個 AI 工具入口都不同

不同 AI 工具會找不同入口檔。這套工具同時放置 AGENTS.md、CLAUDE.md、GEMINI.md,把常見工具導回同一套開工規矩。Antigravity CLI 會讀工作資料夾內的 AGENTS.md 與 GEMINI.md；因此 AGENTS.md 仍是唯一真源,GEMINI.md 只做橋接。

這套工具同時放置三個入口檔,全部指向同一套規則,工具之間沒有漂移
04

AI 會亂改、亂刪

AI 一旦放手做事,可能執行 rm -rf 或 git reset --hard 一類指令;你當下不在電腦前,根本察覺不到。

這套工具內置安全規則,危險指令一律禁止;改檔之前必須先報告計劃
03 / 開工與收工

開工接上狀態,
收工留下交接。

你不需要記住長指令,也不需要自己打開交接文件。新對話在同一專案內說「開工」,AI 會讀取上一輪狀態;準備結束本輪工作時說「收工」,AI 會更新交接文件,並把下一次接力內容寫入提示副本。

04 / 八個常見任務情境

你描述任務,
AI 自動切換工作模式。

你不需要記任何規則名稱,只要用日常話講你要做甚麼。AI 會說明它準備按哪種方式工作,以及為甚麼這樣做。這些規則是給 AI 自己遵守,不是要你逐句閱讀的說明書。

寫代碼

寫 / 改代碼

AI 會先讀項目索引、找測試指令、看相關檔案,再動手;不會一上來就亂改。

研究

查資料 / 做研究

AI 會分清來源、日期、事實、推論、未核實的內容,不把估算當作結論。

寫作

寫文案 / 改 README

AI 會先看受眾、用途、語氣、格式,不會只做漂亮但不準確的文字。

知識整理

整理 Notion / Google Drive

AI 會先判斷外部文件是正式來源、索引、附件還是輸出位置。如已連接 Notion 或 Google Drive,AI 可直接讀寫對應資料來源;未連接則產生需要手動同步的內容。寫入之後必定回讀核對。

溝通

輸出格式 / 報告

AI 會先講結論、再交代背景;標清未核實的內容;指令可直接複製使用。

安全

刪檔 / Git / 外部服務

所有危險指令(rm -rf、git reset --hard、強制推送)一律禁止;改動之前要列出目標、做好備份。

發佈

準備發佈 / 出版

AI 會把「準備版本說明」和「真正發佈、上傳、建立版本」分開處理,不會誤發佈。

規則整理

改規則 / 改流程

AI 會先檢查既有規則能否擴充,以合併為先,不盲目新增,避免規則越疊越亂。

04 / 接入 Handoff Kit

重要文件完成後,
讓下一個 AI 找得到、用得對。

當 AI 新建 stock list、production guide、runbook、workflow、checklist 或研究真源時,不要只把它留在當前對話。你可以直接說「把 docs/production-guide.md 接入 Agent Handoff Kit」,AI 會檢查這份文件是否已登記、何時要讀、哪條流程會更新它,以及是否存在重複真源。

1

兩種常見用法

用法一:指定文件 
把 docs/stock-list.md 接入 Agent Handoff Kit
或舊說法:
治理打通 docs/stock-list.md
或英文:
bridge governance for docs/stock-list.md
用法二:掃描候選 
掃描未接入 Agent Handoff Kit 的重要文件
或英文:
scan for unbridged governance documents

第一種直接審核指定文件;第二種不指定文件,只先掃描 repo 中可能漏接的重要文件。

2

先找候選與缺口

AI 會看文件本身、PROJECT_INDEX、DOC_SYNC_REGISTRY、相關 workflow、handoff/log 角色分工,並搜索是否有同用途舊文件。repo-wide 掃描只列候選,不把普通文件當成錯誤。

3

只列缺口,不亂改

若發現漏接,AI 會列出建議補丁與需要你判斷的項目。掃描不會自動改檔;刪除、重命名、合併真源等動作仍要你明確確認。

05 / 三步上手

由零到第一次成功交接,
大約五分鐘。

你只需要一部已安裝 Node.js 的電腦,以及能讀寫本機專案資料夾的 AI agent,例如 Claude Code、OpenAI Codex、Gemini CLI、Google Antigravity。普通 web chat AI 若不能讀寫本機資料夾,並不適合使用本工具。

1

安裝

最簡單做法:在你的項目資料夾打開能讀寫本機資料夾的 AI agent,貼上:

請讀取 https://adamchanadam.github.io/agent-handoff-kit/agent-handoff-kit-ai-install.html ，並在這個資料夾安裝或升級 Agent Handoff Kit。

AI 應先顯示目前資料夾並請你確認;未確認前不會安裝或升級。想手動處理時,才在終端機執行:

npx --yes @adamchanadam/agent-handoff-kit@latest init

工具會在項目內建立 AGENTS.md、CLAUDE.md、GEMINI.md、dev/ 一系列固定文件。

2

開工

打開能讀寫本機專案資料夾的 AI agent。若 AI 已在正確專案內,新對話只需輸入:

Start Agent Handoff
或
開工

若 AI 還未指向你的專案資料夾,才使用帶路徑啟動句:

Work in <你的資料夾>. Read AGENTS.md first, then Start Agent Handoff. Before changing anything, tell me the current state and your recommended next step.

AI 會依 AGENTS.md 讀取 START_NEXT_SESSION_PROMPT.txt。第一次安裝後,該檔案會載入新手引導;收工後,同一個檔案會保存下一次接力狀態。

若你說的是「某某開工」這類帶其他上下文的話,AI 應先確認是否指本工具接力。

  1. 確認你想做哪一類項目。
  2. 確認資料夾、已有內容與技術方向。
  3. 說明 Handoff Kit 會怎樣記住進度。
  4. 把模糊需求收斂成短小可驗收的第一步。
  5. 等你確認後,才進入正式工作。
3

收工

本輪工作完成、準備結束,只需打:

收工
或
Wrap up Agent Handoff
或
wrap up
或
handoff

若你說的是「某某收工」這類帶其他上下文的話,AI 應先確認是否要執行 Agent Handoff Kit 收工交接。

AI 會自動更新交接文件,並同步更新 START_NEXT_SESSION_PROMPT.txt。下一輪在同一專案內說 Start Agent Handoff 或「開工」即可接力;若 AI 尚未指向資料夾,才使用帶路徑啟動句。

🚀 第一次用?最簡單版本

未安裝或不確定是否要升級時,先在目標資料夾打開 AI agent,請它讀 agent-handoff-kit-ai-install.html 並在這個資料夾安裝或升級。安裝後在同一個 AI agent 輸入 Start Agent Handoff 或「開工」。AI 會打開 START_NEXT_SESSION_PROMPT.txt,再用 5 步引導你:選情境、問背景、解釋會記住甚麼、建議第一個小任務、等你確認後才動手。本介紹頁不需要先讀完。

06 / 為新手而設的安全護欄

就算你不懂代碼,
項目也不會被 AI 弄壞。

這套工具內置「安全」工作模式。任何時候涉及刪檔、Git、雲端寫入、發佈,AI 都必須切換到安全做法,並遵守以下硬性禁區:

  • 禁破壞性指令:rm -rf / git reset --hard / 強制推送 / 系統根路徑操作,一律拒絕。
  • 機密保護:`.env`、API key、token 一類敏感值,不會被印出、不會被提交,也不會被上傳。
  • 查證不猜:使用第三方服務或工具之前要先查官方文件;查不到就標「未核實」,不憑印象亂寫。
  • 權限不足就停手:檔案被鎖或沒有權限時,AI 會列出「手動操作清單」交給你,不會嘗試強行繞過。
改檔之前,
先講計劃。

高風險的工作,例如影響多檔、涉及外部系統、牽涉刪除或重命名,AI 必須先報告完整計劃,等你確認才動手,不會悄悄改動。

07 / 分檔有層次

AI 內部的工作邏輯,
你不需要記。

這套工具把項目資料分成「每次必讀」、「按需要讀」、「追溯時才讀」三層,讓 AI 知道何時讀甚麼。你不需要記這個分層 —— 下面只是讓你了解 AI 如何安排你的項目資料,以便日後你問「我們之前為何這樣做」時,AI 知道從何處找答案。

每次開工必讀

每次必讀

SESSION_HANDOFF:當前狀態、下一步、風險。

PROJECT_INDEX:檔案登記、真源。

AGENTS / CLAUDE / GEMINI.md:開工規則。

AI 開工第一輪會讀齊。你啟動接力後,AI 的第一回應反映你現在做的事。

按需要讀

按任務讀

工作規則:按任務選用的做事守則。

PROJECT_DECISIONS:項目長期演進、決策、學習。

視乎你今日做的任務,AI 自己選擇要讀哪些規則,不需要你決定。長期項目的決策歷史亦放在這裡 —— 遇到「我們之前為何這樣做」的問題時,AI 會在這裡找答案。

追溯時讀

日後追溯

SESSION_LOG 舊條目

平日不讀,做審計或追溯時才打開。AI 收工時自動將舊條目封存至此。

08 / 一目了然

記住三件事,就夠。

01

開新對話,說開工

AI 已在正確專案內時,每次新對話說 Start Agent Handoff 或「開工」。若 AI 尚未指向資料夾,才使用: Work in <資料夾>. Read AGENTS.md first, then Start Agent Handoff.

02

用日常話描述任務

AI 會先用 5 步引導你把需求想清楚,再自行宣告載入哪個工作模式;新手不用記任何規則包名稱。

03

開工接力,收工保存

下一輪說 Start Agent Handoff 或「開工」,由 AI 自己讀取最新提示。準備結束本輪工作時說「收工」或 Wrap up Agent Handoff,AI 會更新交接文件與 START_NEXT_SESSION_PROMPT.txt。
