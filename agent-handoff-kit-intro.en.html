Give the next AI an honest handoff.

Agent Handoff Kit helps local AI agents continue real project work across conversations without pretending they remember everything. It records the current state, useful rules, risks, validation, and the next recommended action in the project itself.

Version note: this source page can be ahead of the published npm package; @latest always means the version currently available from the npm registry.

Why it helps

Conversations reset

A new AI chat often has no reliable picture of what happened before. The kit gives it a small, current starting point.

Files need ownership

It distinguishes exact Kit content from local material. A filename or a familiar heading is never enough proof to overwrite something.

Work needs a real finish

When you actually end a session, closeout leaves a usable handoff instead of a vague chat summary.

Start in three steps

  1. Open a local AI agent in the folder where you want to work.
  2. Ask it to read the AI install page and install or upgrade the kit in that folder.
  3. After it finishes, say Start Agent Handoff. When you are ending the session, say wrap up.
You stay in control. Before any install or upgrade, the AI must show the folder and ask for confirmation. If it finds user-owned or unclear content, it preserves it or stops safely rather than overwriting it.

The everyday flow

You sayThe AI does
Start Agent HandoffReads only the minimum current state, shows the startup card and recommended next action, then waits. It does not start a task by itself.
“Continue the current task”Uses the relevant handoff and rule packs, then starts the requested work.
“Connect this document to the kit”Finds the existing authoritative home and records the route without creating a competing source of truth.
wrap upRuns the project closeout process and leaves the next session a concise, durable handoff.
For users: describe your goal in normal language. The AI is responsible for the technical steps, checks, and explanations.

Two supported upgrade journeys

New projects use the formal user-rules route. Older projects can have direct rules in AGENTS.md. In both cases, the product only changes exact Kit-managed content, retains user bytes, keeps effective rules reachable, and verifies that doctor, report, and success read the same accepted state.
