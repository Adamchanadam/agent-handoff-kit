AI 安裝步驟與檢查

以下交給 AI 執行。用戶只需確認目標資料夾，不用自行選擇安裝指令。

執行前先讀：完成後怎樣回覆

用簡短中文交代：安裝／升級是否完成、已確認的資料夾、檢查結果及提醒、快捷入口狀態，以及一個下一步。doctor 失敗便列出失敗項，不能重裝覆蓋；若只有 START_NEXT_SESSION_PROMPT.txt 提示副本落後，說明正式收工時會更新，不為此重裝。

完成後讓用戶在本專案的 AI 對話使用 handoff-kit-onboard（首次學習）或 handoff-kit-start（接回工作），不是在終端機輸入。Claude Code、Gemini CLI、Antigravity CLI 用 /；Codex 用 $ 或 /skills。未顯示選單時，重新開啟專案對話，Gemini 也可 /commands reload。已安裝不代表原生選單及呼叫已驗證，須如實區分。不要因安裝完成就自行開始已保存的任務。

1. 確認資料夾

顯示目前資料夾的絕對路徑，請用戶確認是否在這裏安裝或升級。未確認前，不執行 init、upgrade 或 doctor。確認後，先檢查是否有未完成升級，再檢查現有交接工具或 AI 工作文件。

只處理本專案，不安裝到共用設定。不刪除、不覆寫衝突、不接觸登入憑證；不執行 git commit、git push、git tag、npm publish，也不建立 GitHub Release。

2. 安裝、升級或恢復

若完全沒有 AGENTS.md、CLAUDE.md、GEMINI.md、START_NEXT_SESSION_PROMPT.txt 或 dev/，執行：

npx --yes @adamchanadam/agent-handoff-kit@latest init --yes --root .

若已有任何交接工具或 AI 工作文件，先預演：

npx --yes @adamchanadam/agent-handoff-kit@latest upgrade --dry-run --root .

預演無衝突，才執行：

npx --yes @adamchanadam/agent-handoff-kit@latest upgrade --yes --root .

若有衝突（conflict），新計畫保持零寫入並停止。AI 應讀取衝突檔案及官方版本，提出保留用戶內容的合併方式，取得具體授權後才修改。內容不明不能當作可覆寫；檔案雜湊只可核對內容有沒有改變，不能判斷內容可否丟棄。合併後重新預演、完成適用的升級，再檢查及讀回內容。不得靠重裝或整檔覆寫繞過衝突；若能證明是未改過的舊官方檔被誤判，向維護者提供版本、來源和雜湊證據。

若已有未完成升級，先按工具指示，用 upgrade --yes --root . 恢復；不能手動刪鎖，也不能以單獨 doctor 取代恢復。首次安裝中斷則重新執行安裝，補齊缺少部分。部分成功不能當作全部完成。

3. 確認結果

讀回同次操作的根目錄、CLI 版本、完整終態及健康結果。只有程序成功退出、安裝完成或升級已提交（或確定無需更新）、沒有未完成交易、健康結果明示通過，且其後沒有相關檔案變更或不明狀態，才可沿用同次 doctor 結果，不必重跑。保留所有提醒；不能只憑版本號或一句「成功」判定。

操作失敗、中斷、輸出不完整或相關檔案其後有變動時，舊結果無效。先恢復未完成升級；沒有待恢復升級但仍缺有效健康結果，或用戶另行要求檢查時，才執行：

npx --yes @adamchanadam/agent-handoff-kit@latest doctor --root .

同次健康檢查不等於再次核對 npm 最新版；要說「已是最新版」，須核對 npm registry、實際 CLI 與安裝版本。預演通過不代替真正完成。正式收工及獨立驗收的另有要求仍適用。

init／upgrade 會在同一次操作安裝及檢查所有專案快捷入口，包括 Codex 的中英文短說明；無須另外啟用。缺漏不能報成功，同版本升級也可補齊。相同內容不改，能確認是未改過的舊官方入口才安全更新；自訂或來源不明的同名內容須停止並保留。

不要為升級猜補工作進度。保留原有交接；下一次正式收工再按已安裝規則整理。新增長期要求時，依已安裝的 dev/rules/agent-governance.md 中 Governance Write Boundary 找合適位置，保護官方正文；舊有混入正文的自訂內容仍按衝突合併處理。
