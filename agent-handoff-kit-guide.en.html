From one request to the next useful handoff.

These three scenarios show the normal rhythm: ask an AI to work in your folder, let it make the technical choices visible, and use a closeout only when you are actually ending the session.

Version note: this source page can be ahead of the published npm package; @latest means the version currently available from the npm registry.

First use

Open a local AI agent in the project folder and ask it to read the AI install page. It confirms the folder before it installs or upgrades. When the result says doctor passed, use:

Start Agent Handoff

A plain startup restores minimum state, presents the card, and waits. If you want it to continue immediately, use one message with explicit intent:

Start Agent Handoff, continue the current task until the next blocker.
This difference matters: starting a session is not permission to silently turn a handoff objective into a long autonomous run.

Three everyday scenarios

1. Organise a downloads folder

You say: “Help me organise the downloads folder. Show me the plan before moving anything.”

The AI does: checks the folder, proposes a reversible plan, makes only the approved moves, and reports what changed.

When you stop for today: say wrap up. The next AI gets the folder context and remaining decisions.

2. Research a café location

You say: “Research three candidate neighbourhoods for a café and keep the evidence organised.”

The AI does: records sources, separates facts from recommendations, and puts new documents through the project’s existing route.

Why the handoff helps: a later session can continue from the accepted evidence instead of repeating the research.

3. Evolve a long-lived AI project

You say: “Review this change, implement the smallest safe fix, and keep the handoff current.”

The AI does: follows the project’s routed rules, validates the change, and records a closeout only at the real end of the working session.

Why the handoff helps: new agents inherit the current objective, risks, and checks rather than chat memory.

Upgrading an existing project

Ask the AI to inspect first. A safe upgrade is not “replace every familiar file”. It may update only content whose package identity and exact bytes prove that it is Kit-managed. Everything else stays unchanged with its real reader, is moved only when its effect is verified, or stops the upgrade before writes.

SituationCorrect outcome
Exact historical Kit core plus a local rule outside itUpdate only the exact core; retain the local bytes; verify the ordinary entry still reads the rule.
Mixed or unknown file that merely looks officialDo not infer ownership from title, language, path, or layout. Preserve it or stop safely.
Interrupted transactionRecover to a complete old or complete new state, then have doctor read the same accepted state as report and success.
Second upgrade after successRe-read the current state; do not manufacture a second transaction or reuse stale evidence.

For the exact commands and required user-facing result, use the AI install page.

A short checklist for users

  1. Tell the AI the outcome you want in ordinary language.
  2. Confirm the folder before it writes.
  3. Read the result and next step, not just a green terminal line.
  4. When you are genuinely stopping the session, say wrap up.
  5. At the next session, say Start Agent Handoff, then explicitly say whether you want it to continue working.
