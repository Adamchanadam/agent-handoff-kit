From the first instruction
to the next handoff

Three complete everyday journeys—tidying a Downloads folder, researching a café business, and evolving a long-running AI project—show Agent Handoff Kit from installation through handoff. At each stage the AI says which working mode it loaded, how it will plan, how it will verify the result, and when it will synchronise the next-session prompt.

Version note: this page is aligned with v0.3.65. The version actually obtained through @latest is determined by the npm registry. Terminal output below is a v0.3.65 example.

🚀 First time here?

You do not need to read this guide first. In the folder you want to work in, open an AI agent that can read and write local folders. Ask it to read agent-handoff-kit-ai-install.en.html and install or upgrade there. After installation, if the AI is already in the correct project, type:

Start Agent Handoff
or: 開工

Only if the AI is not yet pointed at the folder, use: Work in <your folder>. Read AGENTS.md first, then Start Agent Handoff. The AI follows AGENTS.md to the authoritative SESSION_HANDOFF. After a fresh install, a plain start shows the current state, risks and recommended next step, enters the short first-use welcome, then waits for your next message. On an existing upgraded project, a plain start remains status-only; a same-message task starts work directly. START_NEXT_SESSION_PROMPT.txt is only for an AI that has not yet been pointed at the folder. To finish a session, say Wrap up Agent Handoff.

Ordinary web-chat AI that cannot read and write your local folder is not suitable for this tool. This guide demonstrates long-running local-agent work.

AI working rules

The AI does more than read a handoff: it changes working mode for the task

The point of Agent Handoff Kit is not merely to remember where work stopped. After you provide a concrete task, it helps the AI select task-appropriate rules. A plain start recovers state only. A new user needs one simple idea: you state the goal; the AI chooses the working rules; a high-risk operation stops for your approval.

From recovered state to an explicit taskwork begins with your task
1. Start: read the authoritative handoff for current state, next action and risks; read the project index only when the task needs it.

3. Load rules: only relevant packs, not every internal file at once.
4. Work and verify: plan first, read facts, make changes, then check them in a verifiable way.
5. Wrap up: durable state returns to the handoff; one-off output does not pollute long-term rules.

What actually happens

This creates the complete handoff file set

  • Three entries, one rule set: AGENTS.md, CLAUDE.md and GEMINI.md are created together so common AI tools return to the same rules. Antigravity CLI reads AGENTS.md and GEMINI.md in the working folder; GEMINI.md is a bridge, not a separate rule set.

Step 02 · Case A

Start the handoff — first start can onboard; a task starts work

Open a new conversation in an AI agent that can read and write the local project folder. If it is already in the right project, you may type Start Agent Handoff or 開工. On a fresh install with no same-message task, that recovers the minimum state, shows the current objective, risks and recommended next step, enters the short first-use welcome, then waits for your next message. On an existing upgraded project, the same plain start remains status-only. When the platform can safely control the calling conversation’s title, the AI may use already-loaded facts to replace a generic or stale title with <project name>｜<primary action>; readback helps preserve an informative title when available, but is not required if the tool safely targets the calling conversation. Unsupported control is skipped silently; no extra file or network reads are made. The title is display-only, not state, progress, or authority. If you include the goal in the same message, or explicitly say to continue to the next blocker or finish the current objective, the AI may begin under the normal task rules.

What actually happens

The start phrase is not automatic execution authority

  • A plain fresh start can include onboarding: the AI reads only the minimum handoff state, shows the startup card, risks and recommended next step, and may add the first-use welcome, but it does not search, plan or start a task.
  • A same-message task can start: you can write “Start Agent Handoff, tidy my Downloads”; when facts are sufficient, the AI chooses the closest working situation without making you choose A–F.
  • Later guidance needs a real signal: after the first-use welcome is consumed, phrases such as “teach me”, “I’m new” or “help me start”, or a task that still needs clarification, are what load newcomer guidance.

What actually happens

Closeout triggers the full handoff sequence

  • Natural closeout: “收工”, “Wrap up Agent Handoff”, “wrap up”, “handoff”, “end session” and “done for today” route to the same procedure; no long command to remember.
  • Reconciled state: do not append new state below old state. Reconcile each affected section against current facts instead of putting a new date on an old snapshot.
  • Prompt mirror: the convenience copy carries the opening message; a new conversation does not require manually pasting the whole file. The handoff remains authoritative.
  • Threshold-based log maintenance: check maintenance triggers at closeout. Organise or archive only when a threshold applies; otherwise record no maintenance needed. Ordinary startup does not read the log.

What actually happens

Handoff and release safeguards

  • A new AI need not ask for the whole background: entry files and handoff state locate prior progress, next work and risks for a new conversation, tool or day.
  • Cross-tool consistency: Claude, Codex and Antigravity can use the same handoff data; actual entry support follows official tool documentation and local verification.
  • Connected execution plus readback: with GitHub connected and the action authorised, the AI creates, pushes and releases, then reads back the result. Without the integration it provides detailed manual steps.
  • Explicit approval for consequential actions: plan approval excludes commits and tags. Local commit/tag scope and remote repository/push/release scope each need clear authorisation; connectivity does not weaken this rule.
  • Credentials stay separate: the AI tool’s secure store manages GitHub credentials; no credential is written into dev/ governance files.

Case C · structure

This case spans several months and uses a timeline.

Cases A and B show seven-step task journeys. Case C shows a long-running project across multiple conversations and months. The emphasis is not each daily action, but how the AI maintains durable records: requirement evolution, accumulated decisions, historical architectural choices and recurring lessons.
