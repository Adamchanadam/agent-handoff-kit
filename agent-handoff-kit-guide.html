三個日常情景 —— 整理電腦下載目錄、開咖啡店市場調查、長期 AI 項目演進 —— 完整示範 Agent Handoff Kit 由安裝到接力的流程。每一步都會看到 AI 主動宣告載入哪個工作模式、怎樣計劃、怎樣驗收、何時同步下次接力提示。

版本提示：本頁對齊 v0.3.49；@latest 實際取得版本以 npm registry 為準。以下終端機輸出是 v0.3.49 的示例。

🚀 第一次用?

你不需要先讀本指南。未安裝或不確定是否要升級時,在目標資料夾打開能讀寫本機資料夾的 AI agent,請它讀 agent-handoff-kit-ai-install.html 並在這個資料夾安裝或升級。安裝完成後,若 AI 已在正確專案內,輸入:

Start Agent Handoff
或:開工

若 AI 還未指向資料夾,才用帶路徑啟動句:Work in <你的資料夾>. Read AGENTS.md first, then Start Agent Handoff.

AI 會依 AGENTS.md 讀權威 SESSION_HANDOFF。單獨開工只顯示目前狀態、風險與建議下一步,然後等待你下一句;同一句有明確任務時才可直接開始工作。START_NEXT_SESSION_PROMPT.txt 只供尚未指向資料夾的 AI 接入。收工可說 Wrap up Agent Handoff。

普通 web chat AI 若不能讀寫本機資料夾,並不適合使用本工具。本指南示範的是本機 agent 長任務流程。

AI 工作規則

AI 不是只讀交接，也會按任務換工作模式

Agent Handoff Kit 的重點不只是保存上次做到哪裡。它也會讓 AI 在每次開工後，按任務選擇合適的工作規則。新手只需記住一句：你講目的，AI 負責選工作規則；高風險操作要先停下來問你。

工作流程開工後自動發生
1. 開工：AI 先讀權威 handoff 的目前狀態、下一步與風險；專案索引按任務需要才讀。 2. 判斷任務：它判斷你要寫作、開發、研究、整理知識庫，還是處理外部工具。 3. 載入規則：它只載入需要的規則，不把所有內部文件一次塞進上下文。 4. 執行與檢查：先計劃、再讀檔、再修改，最後用可驗收方式檢查。 5. 收工：有長期價值的狀態會寫回交接；一次性輸出不污染長期規則。

  • 不需要你下指令:你不需要叫 AI「整理項目歷史」。AI 在收工階段自動執行紀律,違反即下次收工補做,不靜默跳過。
DAY 60 · CASE C

決策累積 —— 確認決策達 30 條,AI 自動歸檔舊條目

再過一個月,對話次數累積至 15,交接文件的「確認決策」段累積至 32 條。AI 自動偵測到累積邊界,觸發自動歸檔:最舊的條目搬入項目決策日誌的決策封存段,保留最近的 12 條在交接文件作日常使用。

你 · Day 60 收工

收工。

AI · Day 60 收工流程

進行收工流程。偵測到:

  • 交接文件確認決策累積至 32 條,超過 30 歸檔邊界
  • 自動歸檔條件啟動

執行歸檔:

保留在交接文件(最近 12 條):#21 至 #32
搬入項目決策日誌封存(最舊 20 條):#1 至 #20
排序:最新在頂(#20 在最頂,#1 在最底)

交接文件從 32 條確認決策收斂為 12 條當前活躍決策,清楚反映項目目前的判斷邊界。封存段完整保留所有歷史條目,日後追溯用。

同時觀察到:本輪計劃涉及多選項架構取捨(三個後端方案之間作出選擇,並記錄原因)。自動補入架構取捨段:

### 2026-XX-XX:後端處理由方案 A 切換至方案 B
比較選項:(1) 方案 A:低成本但上下文較短 / (2) 方案 B:上下文較長但成本較高 / (3) 方案 C:速度較快但格式控制較弱
選擇:方案 B
原因:程式碼註釋校對需要保留較長上下文;方案 B 在本項目的測試樣本中較穩定。
影響:後端 API 呼叫需要重寫;提示模板需要重新調整。
實際運作

自動歸檔與架構取捨同時觸發

  • 歸檔屬硬性自動執行:30 條為硬性邊界。確認決策累積至 30 或以上必歸檔,不會因任務性質而豁免。保留 8 至 22 條在交接文件,具體保留數視乎內容連貫性(避免突然切斷一組相關決策)。
  • 多選項取捨的明確補入條件:計劃階段列出兩個或以上候選路徑 + 選擇其中一條 + 記錄原因 —— 三個條件同時滿足才補入。簡單「我選 A 或 B」式二擇一不觸發,因為缺原因紀律。
  • 交接文件仍是接力來源:即使確認決策歸檔過,交接文件仍含當前活躍決策。新對話接力只需讀交接文件加項目索引,不需要讀項目決策日誌。後者只在「之前為何這樣做」的回顧查詢時才被讀。
DAY 90 · CASE C

回顧問題 —— 你問「之前為何選方案 B?」,AI 查歷史答你

再過一個月,項目已試用。某日合作伙伴問你:「為何當時選方案 B,而不是成本較低的方案 A?」你不記得具體原因細節 —— 但你知道 AI 有紀錄。打開新對話,問 AI。AI 讀交接文件加項目索引後,主動查項目決策日誌。

你 · Day 90 新對話

我們之前為何選擇方案 B,而不是成本較低的方案 A 做後端處理?合作伙伴現在問我。

AI · 查歷史

交接文件當前目標提及後端使用方案 B,但原因細節不在當前狀態。讀項目決策日誌的架構取捨段:

### 2026-XX-XX:後端處理由方案 A 切換至方案 B
比較選項:(1) 方案 A:低成本但上下文較短 / (2) 方案 B:上下文較長但成本較高 / (3) 方案 C:速度較快但格式控制較弱
選擇:方案 B
原因:程式碼註釋校對需要保留較長上下文;方案 B 在本項目的測試樣本中較穩定。
影響:後端 API 呼叫需要重寫;提示模板需要重新調整。

原原因兩點:(1) 任務需要保留較長上下文;(2) 方案 B 在本項目的測試樣本中較穩定。當時切換時 Day 60 工作日誌有完整紀錄,如需細節追溯我可以查封存。

你可以直接將此原因答給合作伙伴。

實際運作

回顧查詢的完整流程

  • 當前狀態不夠就查長期紀錄:AI 開工讀當前狀態已足夠處理今日任務。當你提出回顧問題(「之前為何」「最初設計是甚麼」「哪輪對話改了這項」),AI 自動翻看項目決策日誌。
  • 不需要你記得文件名:你只需要問問題,AI 自己會去找。你不需要記內部結構,亦不需要記 AI 的自動維護紀律。
  • 三層追溯:當前狀態 → 項目決策日誌 → 工作日誌封存。如項目決策日誌的紀錄不夠詳細,AI 可進一步查工作日誌封存對應批次,找到當時收工的完整描述。
  • 新手用戶全程感覺不到:你從來沒有打開過項目決策日誌,亦沒有打開過工作日誌封存,沒有記任何結構 —— 但你的項目歷史紀錄全部完整保留,AI 隨時可以幫你查回。

走完三個案例之後,你會發現 同一套流程 適用於不同任務

由 AI 讀安裝指令頁判斷安裝或升級,或手動用終端機安裝 —— 開新 AI 對話啟動接力 —— 單獨開工先看狀態與建議下一步,有任務時才開始做 —— 計劃階段停手等你確認 —— 涉及安全、知識整理、寫作時自動加上相應規則 —— 準備結束本輪工作時一句「收工」自動寫好下次提示 —— 新對話說「開工」就接得回狀態。Case A 與 Case B 各七步,Case C 則跨越多月演進,但骨幹節奏跨案例、跨工具、跨日子都是同一套。

你之後做第三個、第四個任務 —— 寫電子報、做股市觀察、整理多個項目的發票 —— 流程仍然是這套。工作模式會根據任務性質自動切換,但你的習慣動作(開工看狀態、講任務、確認計劃;準備結束本輪工作時收工)始終一樣。

另外建議:你希望 AI 在單一對話內的做事規矩(語氣、優先序、回覆骨架、安全護欄、輸出層分工)有持久基準,可以配合 Adam-AI-Instructions 使用 —— 到該倉庫的「五、提示詞索引」選擇適用版本,複製對應 prompt.md 全文貼入你 AI 工具設定。Agent Handoff Kit 管「對話之間」的接力,Adam-AI-Instructions 管「單次對話質素」,兩者不重疊。
