# v0.3.26

## 本版新加了甚麼

這版修補升級後 `doctor` 可能誤報的問題。若交接欄位已經用自然語言說明「某件事曾被列為 pending，現在已記錄或已解決」，工具不應只因句中出現 `pending` 這個字，就判斷交接仍未完成。

同時，若規則包被放到錯誤層級，工具會提供較清楚的診斷，協助 AI 判斷應補回正確位置，而不是讓使用者面對模糊的缺段錯誤。若上一版安裝後的 `AGENTS.md` 內容已是最新但缺少 managed marker，正式升級也會補回標記，避免看似最新卻沒有完整機器邊界。

## 對你已有檔案的影響

本版不改你的工作方式，也不要求重寫交接內容。升級會保留既有 handoff、log、index、decisions 與 rule pack 內容；工具只修正檢查判斷，讓合法的交接敘述不再被誤擋。

如果你的舊交接文件曾因 lifecycle 欄位中段出現 `pending` 而令 `doctor` 失敗，升級後應可直接通過。真正仍以 placeholder 開頭、或明確表示 unresolved 的欄位，仍會被工具擋下。

## 建議下一步

既有項目可直接升級：

```text
npx --yes @adamchanadam/agent-handoff-kit@latest upgrade
```

升級後照常在能讀寫本機資料夾的 AI 對話輸入 `Start Agent Handoff` 或「開工」。如 `doctor` 仍指出交接矛盾，請把輸出交給 AI 處理；不要重新 `init` 覆寫既有項目。
