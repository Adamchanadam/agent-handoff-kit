# v0.3.52

## 本版新加了甚麼

- 新增 manifest-bound `reconcile-current-state`：先以 dry-run 產生計劃與 SHA-256，再以 `--yes --manifest <sha256>` 執行同一份已核對計劃。
- 可接受範圍只包括精確六份直接 closeout state、安全可證的 formal user sources，以及完整合格的 canonical archive group；任何不合格項目都會阻止整份計劃。
- reconciliation 只寫既有 journal / report / lock 證據，不覆寫、複製、移動或刪除專案內容。init / upgrade 不能繞過 manifest authority 代為恢復它，原有安裝、升級、收工、健康檢查及 recovery 保護亦沒有放寬。
- 明示 `Start Agent Handoff` /「開工」在平台安全支援標題讀回與控制時，可把 generic / stale title 改成簡潔的 `<project name>｜<primary action>`；只使用已載入事實，不額外讀檔或連網，不支援時靜默略過。

## 對你已有檔案的影響

當 user-owned formal source 或 canonical archive 經過有意修改後，Kit 現在有一條保守、可核對且不改寫專案內容的重新綁定路徑。對話標題只是顯示用衍生資訊，不是狀態、進度、完成證據、健康結果或額外授權；單獨開工仍只顯示狀態與建議下一步，然後交回控制。

## 建議下一步

如你的專案已安裝 Kit，請在專案資料夾告訴能操作本機檔案的 AI：「把 Agent Handoff Kit 升級到最新版，先預演並檢查，確認安全後再套用。」若只想繼續現有工作，說「開工」即可；支援的平台會嘗試使用較易分辨的工作標題，不支援時不影響交接。
