# v0.3.54

## 本版新加了甚麼

- 交易收據只在本次 `init` / `upgrade` operation 內用來做 no-clobber、rollback、recovery 與誠實報告；lock 清除後，舊 committed journal 不再成為目前 workspace bytes 的權威。
- `doctor` 與 `upgrade` 在沒有 active lock 時會忽略歷史 committed journal，即使那些舊 journal 已不再匹配日常修改後的檔案。
- active `.upgrade.lock` 仍嚴格保護：只能讀 lock 精確引用的 journal 與 transaction-owned stage / backup / target / archive。lock 空白、半截、不可讀或 schema 無效時，工具會零寫入 fail closed，保留原 lock 供人工判斷。
- 移除手動補綁目前狀態的路線；不再需要 `reconcile-current-state`、`finalize-closeout`、journal edit、repair 或 bless 才能讓正常 mutable workspace 繼續健康。

## 對你已有檔案的影響

v0.3.53 已修掉很多 whole-root 與 generic reference 問題，但在真實會持續變動的 workspace 裡，舊 committed transaction witness 仍可能被誤用成永久 bytes 權威，令正常 source / governance / handoff 修改後被擋在 `committed Gate 5 current-state source witness no longer matches project bytes` 一類錯誤。v0.3.54 把這條權威刪掉：普通檔案、Unicode 路徑、新檔、一般 docs 或 outputs 不會只因舊收據存在而被讀取、hash、報告或阻擋。

Kit 自己管理的 current lifecycle 仍然保守。managed core、正式 USER_RULES、PROJECT_INDEX 結構、archive casing、credential 檢查、active transaction recovery 與 typed unsafe state 仍會 fail closed，不會因移除歷史 bytes witness 而放寬。

## 建議下一步

如你目前被 v0.3.53 擋在舊 current-state witness 或 unbound success state，先不要手改 journal，也不要尋找 reconcile / finalize / repair 命令。等待 v0.3.54 正式發布後，請在隔離副本或你確認可操作的專案資料夾，由能讀寫本機檔案的 AI 執行 `upgrade --dry-run`、確認安全後 `upgrade --yes`，再跑 `doctor`。若專案內仍有 active `.upgrade.lock`，先照工具錯誤處理該 active operation；不要刪 lock 或把舊 journal 當作手動修復依據。
