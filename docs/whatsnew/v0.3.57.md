# v0.3.57

## 本版新加了甚麼

- `closeout-status` 若 fresh doctor read-back 失敗，會直接列出第一個安全、可操作的 doctor blocker，讓 AI 看到真正要修哪一項。
- `closeout-status` 不再把開場白背景資料、已清除 blocker 句，或「只監察／如有新失敗才重開」誤判成未解事項；但真的叫下一輪繼續做已完成工作的開場白仍會擋住。
- 升級安全檢查加入舊 schema-2 committed `currentStateWitness` 回歸情景，防止歷史交易收據再次被誤當成目前狀態權威。
- 單獨 `Start Agent Handoff` /「開工」在支援的 runtime 裡，若標題工具需要先發現，AI 會先做一次窄範圍 title/rename/current-thread 工具搜尋，再用安全的當前對話標題工具改名。

## 對你已有檔案的影響

這版不要求你手動改既有 handoff，也不會把舊交易 journal 當作要你回復檔案的依據。完成的歷史交易仍是收據；沒有 active lock 時，不是目前 byte authority。

開工標題仍只是 display-only：不是任務授權、進度、完成證據、健康結果或新的真源。AI 不應為了命名而查看或管理無關對話。

## 建議下一步

發布後在已安裝 Agent Handoff Kit 的項目執行 `upgrade`，再跑 `doctor`。之後照常用「開工」接續，用「收工」保存交接；若 `closeout-status` 顯示 blocked，先按它列出的第一個 blocker 修正。
