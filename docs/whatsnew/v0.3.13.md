# v0.3.13

## 本版新加了甚麼

本版修正升級後自動檢查失敗時的下一步提示。若 `upgrade` 已經執行，但自動 `doctor` 發現某個保留檔案真的缺少必要段落，CLI 會列出缺失檔案、檢查名稱與缺少文字，並給出交給 AI 非破壞性修補的步驟；不再只叫新手回頭跑 `upgrade --dry-run`。

同時，本版把可重用操作程序的歸位規則收斂到既有 `agent-governance` pack：長期操作方法應進入相關 rule pack 或已登記 reference，不應只寫入 handoff / log 當作完成。

## 對你已有檔案的影響

既有項目不用重裝。`START_NEXT_SESSION_PROMPT.txt` 仍只是 closeout 便利副本；若它只是落後於 `dev/SESSION_HANDOFF.md`，普通 `doctor` 只會提醒，不會把項目判定為失敗。

若升級後看到 anchor 缺失，代表某個保留檔案缺少 Kit 需要的固定段落。工具不會覆寫你的內容；你應把完整 `doctor` 輸出交給 AI，請它按缺失文字補回對應段落。

## 建議下一步

升級前可先預演：

```bash
npx --yes @adamchanadam/agent-handoff-kit@latest upgrade --dry-run
```

如果預演沒有 conflict，再執行正式升級。正式升級後若自動檢查失敗，請按 CLI 顯示的「怎樣修」步驟交給 AI 修補；不要把 `upgrade --dry-run` 當成修補動作。
