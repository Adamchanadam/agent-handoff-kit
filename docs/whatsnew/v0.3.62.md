# v0.3.62

## 本版新加了甚麼

- Kit 現在明確分清 `SESSION_HANDOFF.md` 是已保存的接力快照，不是任務進行中每一步都要同步的即時真源。
- 任務中途 handoff 合理落後於已讀回的任務文件、spec、issue 或外部結果時，AI 不應把它當成 drift，也不應為了鏡像每個中間步驟而重寫 handoff。
- `closeout-status` 會用唯讀 worktree 健康讀回，阻止 handoff 錯誤聲稱「沒有平行 worktree」等 Workspace Identity 假綠燈。
- QA 通過後會自動清理成功的暫存 fixture；只有失敗或明確保留 evidence 時才留下目錄。

## 對你已有檔案的影響

升級不會自動改寫你的工作內容。之後 AI 做普通任務時，應先按任務本身的真源和局部驗收工作；只有有下一輪必須知道的狀態、可能中斷、handoff 是最小正確 home，或進入「收工」時，才按 Kit 的 persistence gate 保存。

如果你的項目使用 Git worktree，收工時 handoff 內的 Workspace Identity 需要與真實 Git / worktree 狀態一致；不一致時會被 `closeout-status` 擋住，避免下一個 AI 接到錯誤交接。

## 建議下一步

發布後在已安裝 Agent Handoff Kit 的項目執行 `upgrade --dry-run`，確認沒有 conflict，再執行 `upgrade --yes` 和 `doctor`。日常工作按任務本身驗收；準備結束本輪工作或有下一輪必須知道的狀態時，再說「收工」保存交接。
