# v0.3.23

## 本版新加了甚麼

交接更乾淨。下一輪 AI 不應被上一輪的臨時驗收、舊版本狀態、發佈證據或一次性任務要求帶偏。這版新增檢查，會把這類內容擋在當前交接之外，要求它們留在紀錄、索引或長期決策檔的正確位置。

研究導向的長期決策也更可追溯。如果某個長期策略、公開說法或治理規則來自外部 research，決策檔要保存簡短 evidence chain，並用 `source:<id>` 對回項目索引中的來源登記。

開工與收工卡片的版本顯示也更穩定。AI 會從 `dev/PROJECT_INDEX.md` 的 `Agent Handoff Kit template version` 讀取版本；讀不到時顯示 `version unverified`，不會把 `v<version>` 佔位符直接輸出。

## 對你已有檔案的影響

升級會保留你的既有內容。若舊項目缺少新的 handoff / log / decisions 欄位，`upgrade` 會在可信位置非破壞性補回，並建立備份與 migration report。

升級不會把舊紀錄改寫成新結論。若 `doctor` 發現 Durable Anchors、Next Priorities 或 opening message 裡混入舊驗收、舊版本或 source evidence，它會要求你讓 AI 在收工時重新歸位。

## 建議下一步

既有項目可直接升級：

```text
npx --yes @adamchanadam/agent-handoff-kit@latest upgrade
```

升級完成後可執行：

```text
npx --yes @adamchanadam/agent-handoff-kit@latest doctor
```

若 `doctor` 指出當前交接混入歷史證據，請打開能讀寫該專案資料夾的 AI agent，要求它把一次性驗收、舊版本狀態與 source evidence 移回 `dev/SESSION_LOG.md`、`dev/PROJECT_INDEX.md` 或 `dev/PROJECT_DECISIONS.md`。
