# v0.3.16

## 本版新加了甚麼

本版修正收工交接流程中一個容易漏過的同步坑：AI 可能只在對話表面顯示下一次開工提示，卻沒有先把同一份內容寫回 `START_NEXT_SESSION_PROMPT.txt`。

現在核心收工規則改為先從 `dev/SESSION_HANDOFF.md` 的權威 opening message 重生 `START_NEXT_SESSION_PROMPT.txt`，再讀回這份便利副本，最後才把讀回內容貼給使用者。這樣 handoff、便利副本、final response 不會變成三份各自手寫的提示。

本版同時把這條收工次序加入發佈前驗收與舊核心升級驗收。若未來 runtime core 退回「先表面輸出、後重生 prompt」的舊次序，`qa:release` 或 `qa:upgrade` 會在 publish 前擋下。

## 對你已有檔案的影響

既有項目不用重裝。升級後，`AGENTS.md` 的 closeout contract 會帶入新的 read-back discipline；本地既有規則仍會保留。

`START_NEXT_SESSION_PROMPT.txt` 仍只是下次開工方便複製的副本，權威內容仍在 `dev/SESSION_HANDOFF.md`。session 進行中若便利副本落後，普通 `doctor` 仍只會提醒；真正要求一致的是 full closeout 完成前。

## 建議下一步

已安裝舊版的項目可先預演：

```bash
npx --yes @adamchanadam/agent-handoff-kit@latest upgrade --dry-run
```

如果預演沒有 conflict，再執行正式升級。之後請在每次完成工作時直接叫 AI「收工」，讓它更新 handoff、重生 `START_NEXT_SESSION_PROMPT.txt`，並把同一份讀回內容交給你下次開工使用。
