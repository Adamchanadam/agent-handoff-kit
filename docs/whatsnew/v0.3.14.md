# v0.3.14

## 本版新加了甚麼

本版修正舊版項目跨版本升級時的交接狀態誤判。部分由很早期版本升級的項目，`upgrade` 會補入新的 lifecycle 欄位；舊工具曾把欄位填成 `TBD`，然後同一次升級後自動 `doctor` 又把這個 `TBD` 判定為失敗。

現在升級工具會把這類欄位明確標記為「由升級重新分類，下一次 closeout 再核對」，避免工具自己寫入一個會被自己拒絕的值。

同時，本版把 rules / packs 路由與可重用程序入庫範圍加入發佈前全面檢，確認自然語言任務能導向相應 pack，而不是隨意新建治理文件或只寫在 handoff / log。

另外，本版把 `START_NEXT_SESSION_PROMPT.txt` 與 handoff opening message 的比對方法收斂到固定檢查器。檢查器會先錨定真正的下一次開工訊息，再正規化 CRLF / LF 換行符，避免只因換行風格不同就誤報內容不一致。

## 對你已有檔案的影響

既有項目不用重裝。若你是由舊版 Kit 升級，工具可能會在 `dev/SESSION_HANDOFF.md` 補入 lifecycle consistency 欄位；這是為了讓下一次 closeout 能核對「已完成的事是否仍被帶成未解待辦」。

工具仍會保留既有交接內容，不會用新版模板覆寫你的工作紀錄。若 `doctor` 指出其他真實缺失，仍應把完整輸出交給 AI 非破壞性修補。

若只出現 prompt convenience copy 的換行符差異，這不是內容損壞；正常 `doctor` 不會因此阻擋你繼續工作。

## 建議下一步

已安裝舊版的項目可先預演：

```bash
npx --yes @adamchanadam/agent-handoff-kit@latest upgrade --dry-run
```

如果預演沒有 conflict，再執行正式升級。升級後若自動 `doctor` 通過，即可繼續使用；若仍有缺失，請把完整檢查輸出交給 AI 修補，不要用重裝覆寫既有內容。
