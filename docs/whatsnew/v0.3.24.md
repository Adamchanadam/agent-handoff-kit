# v0.3.24

## 本版新加了甚麼

`upgrade` 的成功判斷更可靠。若項目檔案已是最新版本，但完整 `doctor` 健康檢查仍未通過，工具不會再說「你已經是最新版本，可以繼續使用」。

這版把 no-op upgrade 的結尾綁回同一套 `doctor` 健康檢查。換句話說：沒有檔案需要建立或合併，不等於交接狀態健康；只有 `doctor` 通過，`upgrade` 才會用成功語氣。若問題屬於工具可安全判斷的 Kit-owned 結構或熱層污染，`upgrade` 會自行修復再驗收。

更重要的是，這版把交接寫入方式收斂到同一套固定標識。新版本之後，handoff、session log、next-session prompt 都要用同一套 `ack:*` marker 作機器邊界；自然語言標題只給人閱讀，舊標題 fallback 只用來遷移舊資料。

正式升級時也一樣。工具會先說 Kit 檔案已更新，然後跑 `doctor`；只有 `doctor` 通過後，才會說升級驗收完成。

## 對你已有檔案的影響

若 `doctor` 發現 opening message 缺必要保護句、歷史 npm / GitHub Release 證據污染熱層、或 `START_NEXT_SESSION_PROMPT.txt` 仍帶舊狀態，`upgrade` 會自行修復這些明確屬於 Kit 檔案健康的問題。

若你的 `SESSION_LOG` 來自舊版本，升級會盡量非破壞性補上新的 session log marker，保留原有紀錄內容。這是為了避免日後再靠自然語言猜每條紀錄的邊界。

若問題需要判斷用戶真實意圖，例如已完成任務是否仍應留在 Next Priorities，工具不會猜。這類狀態會列出失敗原因，請交給能讀寫該資料夾的 AI 做語意整理；不要重裝覆寫。

若你的項目已經健康，再次執行 `upgrade` 仍會保持短輸出，並明確說明沒有檔案需要建立或合併。

## 建議下一步

既有項目可直接升級：

```text
npx --yes @adamchanadam/agent-handoff-kit@latest upgrade
```

升級或重跑後，如工具顯示 `doctor` 未通過，代表剩下的是工具不能安全代你判斷的狀態問題。請不要重裝覆寫；把輸出交給該項目的 AI，按失敗項修補交接內容。
