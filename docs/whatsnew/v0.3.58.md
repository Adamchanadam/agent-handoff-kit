# v0.3.58

## 本版新加了甚麼

- 新用戶首次安裝後，第一次只說 `Start Agent Handoff` /「開工」且沒有同句明確任務時，AI 會進入新手引導。
- 升級用戶不會被重設成新手；已完成或不適用的 onboarding 狀態會保留。
- fresh install 和只補齊缺檔的 create-only install / upgrade 不再建立 `dev/governance_migrations` 或 `.upgrade.lock`。
- 已完成 create-only `init` 留下的過期 `.upgrade.lock` 會被安全讀回後視為歷史證據，不再要求 AI 刪除它。
- 日常 quick QA 新增 install-lock smoke，發佈前 QA 也會檢查這類事故不漏驗。

## 對你已有檔案的影響

一般既有項目升級時仍保留原有 handoff、rules、文件與已消耗的 onboarding 狀態。真正需要合併或覆寫的升級交易仍使用 lock 保護；只有純新安裝或 create-only 補檔路徑避開 migration transaction。

如果你的項目曾因過期 create-only `init` lock 卡住，新版會在 hash、journal、host / pid 與狀態都確認安全時繼續，不再要求 AI 先刪 `.upgrade.lock`。不安全或不完整的 lock 仍會停手，避免覆寫或誤復原。

## 建議下一步

發布後在受影響項目執行 `upgrade --dry-run`，確認沒有 conflict，再執行 `upgrade --yes` 和 `doctor`。新安裝用戶完成安裝後，直接在 AI 對話輸入 `Start Agent Handoff` 或「開工」即可。
