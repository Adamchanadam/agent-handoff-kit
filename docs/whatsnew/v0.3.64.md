# v0.3.64

## 本版新加了甚麼

- 未叫「收工」或明確 checkpoint 時，AI 不能只因「怕下一輪讀錯」就提早寫 `dev/SESSION_HANDOFF.md` 或 `dev/SESSION_LOG.md`。
- 若真的需要 session 中途 checkpoint，AI 要先判斷是否有不可重建、會影響下一步的 durable fact，並只寫最小正確位置；不會重生 `START_NEXT_SESSION_PROMPT.txt`。
- Handoff 增加冷區保護：歷史段落、證據段、已完成紀錄與舊決策不可為了同步語氣、格式或「順手整理」而整段翻新。
- 用戶已提供清楚任務計劃時，AI 會先完成該任務的主驗收；治理只是輔助，不能把普通任務轉成 repo-wide governance scan、bridge flow 或 handoff 寫入。
- 合法治理情況仍保留，例如用戶明示要接入治理、任務本身就是治理、內容需要跨 session 強制約束，或不保存會造成安全、連續性、真源或可發現性 blocker。

## 對你已有檔案的影響

升級不會改寫你的工作內容。影響主要在 AI runtime 行為：日常任務應更少被 handoff / log 寫入、全檔 handoff 翻新或治理支線打斷；真正需要保存的交接狀態仍會透過 Persistence Gate 留在正確位置。

這版也加入 dry-run / hash fixture：普通文檔工作、`doctor` 與 `upgrade --dry-run` 不應改動 `SESSION_HANDOFF.md`、`SESSION_LOG.md` 或 `START_NEXT_SESSION_PROMPT.txt`。若未來有人把「只是同步」變成偷寫，QA 會更早擋住。

## 建議下一步

發布後在已安裝 Agent Handoff Kit 的項目執行 `upgrade --dry-run`，確認沒有 conflict，再執行 `upgrade --yes` 和 `doctor`。之後可用普通任務加一句「不要收工」做 dry-run 驗證：AI 應只完成任務，不提早寫 handoff / log。
