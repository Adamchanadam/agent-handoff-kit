# v0.3.48

## 本版新加了甚麼

- 修補 v0.3.47 的升級阻塞：舊專案若已接受 lowercase `dev/session_log_archive` witness，升級到新版時會在同一 transaction 內遷移到 canonical `dev/SESSION_LOG_archive`。
- rollback 會還原 legacy archive 的精確 bytes；若升級在 archive staging 後中斷，下一次會先 recovery 再重試，不留下半修狀態。
- `doctor` 仍然嚴格；遇到 ambiguous archive layout 會停手，不會猜測合併。
- QA 分層改為 manifest-owned：quick / full / postpublish 的檢查成員與 release-readiness full-suite inventory 由單一 QA manifest 集中定義，減少分散硬編 gate。
- 發佈檢查加入 published v0.3.41 -> published v0.3.45 產生的 accepted current-state witness + legacy lowercase archive 相鄰組合，並用 packed candidate tarball 驗證升級後 closeout / finalize。

## 對你已有檔案的影響

若你的專案停在 v0.3.45 或相近版本，且歷史 witness 綁定的是 `dev/session_log_archive`，新版 `upgrade --yes` 會把 archive casing 遷移納入 upgrade transaction。成功後專案會使用 canonical `dev/SESSION_LOG_archive`；若過程失敗或 rollback，原本 lowercase archive bytes 會保留。

一般 rule pack conflict 仍會 safe stop；新版不會自動覆寫使用者改過的規則檔，也不會把非收工漂移收進合法 witness。

## 建議下一步

升級既有專案時仍先讓 AI 讀 AI install page，跑 `upgrade --dry-run`。若 dry-run conflict 為 0，再執行正式 `upgrade --yes`；完成後跑 `doctor`。如果有 rule pack conflict，先停手逐檔審核，不要重裝或手動覆寫。
