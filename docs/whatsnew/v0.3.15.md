# v0.3.15

## 本版新加了甚麼

本版修正一個真實舊項目升級後仍會被自動檢查擋住的情況。

如果項目已經有新版 lifecycle 欄位，但欄位值仍是舊模板留下的 TBD，而 `Completed This Session` 或 `Validation / QC` 已經有實際內容，舊版升級流程可能只更新版本 metadata，沒有修正這個舊 placeholder。結果是工具先顯示升級完成，隨後同一次自動 `doctor` 又判定 handoff lifecycle consistency 缺失。

現在 upgrade 會在確認項目記錄版本落後於目前 CLI 時，安全地把這類舊 placeholder 重新分類為 upgrade migration 狀態，並保留原有交接內容。這令升級後自動檢查能通過，同時仍要求下一次 closeout 正常核對已完成工作、下一步和風險是否一致。

本版同時把這個真實路徑加入發佈前自動場景檢查，作為 `qa:release` scenario 3c；未來候選版本若再出現相同組合，會在 publish 前被擋下。

## 對你已有檔案的影響

既有項目不用重裝。若你的項目本來已經有 lifecycle 欄位，但欄位仍是 TBD，upgrade 可能會把該欄位改成 `Reclassified at upgrade` 說明。這是工具對舊模板狀態的安全遷移，不會覆寫你的 Completed、Validation、Next Priorities 或其他工作紀錄。

若 handoff 本身真的仍有完成事項與待辦事項互相矛盾，下一次 closeout 仍應由 AI 正常整理；本版只處理舊 placeholder 造成的升級自撞，不把 AI 對專案內容的判斷交給 installer 猜測。

## 建議下一步

已安裝舊版的項目可先預演：

```bash
npx --yes @adamchanadam/agent-handoff-kit@latest upgrade --dry-run
```

如果預演沒有 conflict，再執行正式升級。升級後若自動 doctor 通過，即可繼續使用；若仍有缺失，請把完整檢查輸出交給 AI 修補，不要用重裝覆寫既有內容。
