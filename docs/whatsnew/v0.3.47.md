# v0.3.47

## 本版新加了甚麼

- 升級後正常收工現在有正式補綁路徑：更新交接、日誌和下次開工提示後，可執行 `finalize-closeout` 把合法收工狀態重新記錄為健康狀態。
- `doctor` 仍會先擋住未補綁的 post-upgrade closeout，避免把未記錄的新狀態誤當成已綁定成功狀態。
- `finalize-closeout` 只接受收工相關檔案變動；若同時混入 `AGENTS.md` 等非收工檔案漂移，會停手並要求先處理。
- `doctor` 新增 `dev/SESSION_LOG_archive` 大小寫檢查，避免 Windows 上 `dev/session_log_archive` 和 canonical 路徑混用。
- 發佈檢查加入相鄰版本升級後收工回歸測試，日後不只驗「升級當下健康」，也驗「升級後仍能正常收工」。

## 對你已有檔案的影響

本版不會自動改寫你的交接內容。它補上的是升級後收工的合法完成路徑：如果升級剛完成後你又正常收工，先完成手上的交接更新，再讓 AI 執行 `finalize-closeout`，然後重新跑健康檢查。

## 建議下一步

升級到 v0.3.47 後，若 `doctor` 在正常收工後提示 `unbound success state`，不要手動刪改治理紀錄。先確認只改了交接、日誌、下次開工提示等收工檔案，再執行 `finalize-closeout`。
