# v0.3.59

## 本版新加了甚麼

- `doctor` 會先檢查 `AGENTS.md` 與 `dev/USER_RULES.md` 的正式接受見證，再決定是否可以給一般 anchor 修復建議。
- 如果 `AGENTS.md` managed core 已被 `dev/USER_RULES.md` 的 `managedCoreSha256` 綁定，缺少 anchor 不會再被引導成手動補段落。
- 新增 QA regression：accepted user-rules 狀態下故意製造 managed-core anchor drift，必須先被 user-rules 見證拒絕，而且不得輸出泛用 anchor repair guidance。
- QA 策略加入 cross-contract false-green 規則，複合行為不能再只靠單一 anchor、hash 或 schema check 宣稱可靠。

## 對你已有檔案的影響

這版不會自動改寫你的 user rules。若 `doctor` 報 `AGENTS.md` 與 `dev/USER_RULES.md` 的接受見證不一致，請不要手動補 `AGENTS.md` managed core anchor，也不要覆寫 `dev/USER_RULES.md`。

正確方向是先還原已接受的 managed core，或讓正式 upgrade transaction 重新建立完整的 user-rules 接受紀錄。

## 建議下一步

發布後在受影響項目執行 `doctor`。若看到 formal user-rules 見證錯誤，保留完整輸出交給能讀寫該資料夾的 AI；不要只按缺失 anchor 手修。
